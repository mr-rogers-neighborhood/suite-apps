This tour follows one gesture rather than one file: a value is typed into a field,
committed as one document change, projected back into the board, snapshotted and
written to the user's file. Two rules run through it. One gesture is one undo step,
and a save is this window's edits rather than every change the CRDT has seen.

## apps/canvas/src/cards/PropertyField.tsx#FieldValueInput

The gesture starts as a local draft. The control holds the typed text, and the
document still has the old value, so a keystroke cannot become a write. The commit
happens on blur, and an unparseable number or date is cancelled instead of stored.

## apps/canvas/src/cards/CardBodyEditor.tsx#CardTitleEditor

The title is the other edit path. It is a single paragraph in its own container, so
renaming a card does not touch its body, and Enter commits unless the `@` picker is
consuming the key. An empty title is drawn as decoration, not written as text.

## apps/canvas/src/editor/LoroCollaboration.ts#LoroCollaboration

Each editor binds one container and owns its undo stack. Origins belonging to
another surface, and the structural `struct:` prefix, are excluded, which is why a
text keystroke and a layout change do not share one history.

## apps/canvas/packages/graph/src/loro/facade/cards.ts#CardsFacade.setProperty

The field write reaches the document here. It validates the value, refuses a
read-only session and touches one property rather than replacing the card, so two
people editing different fields keep both writes.

## apps/canvas/packages/graph/src/loro/context.ts#DocContext.commit

One change leaves the facade. The commit's origin is also the change message, so
the edit arrives as one history point and the undo panel can name it.

## apps/canvas/packages/graph/src/loro/WorkspaceDocument.ts#WorkspaceDocument.batch

A gesture that needs several facade calls is one batch. Structural edits use it so
that a create, a title, a property and a link land together; a promotion or a
template install that committed piecemeal would cost one undo press per call.

## interlude: What the board sees

The write is already true for the document. These next stops are how the rest of
the app learns about it without copying it.

## apps/canvas/src/store/workspaceSnapshotStore.ts#WorkspaceSnapshotStore

The projection applies the change to the previous snapshot and keeps the identity
of what did not move. A card whose record changed gets a new object; the board
around it does not.

## apps/canvas/src/store/workspaceStore.ts#useCard

A narrow subscriber asks for one card by id, so a field edit re-renders that card
rather than every card on the board. The value it reads is the document's, not a
React or Zustand copy.

## interlude: What the file gets

A document change is not a save. The last stops are the path that turns local edits
into bytes a backup can hold.

## apps/canvas/src/store/useCanvasStore.ts#useCanvasStore

The store holds the adapter and the one `flush` action that asks persistence to
catch up before a publish or a close. It does not assemble the file or decide where
it goes.

## apps/canvas/src/storage/desktopPersistence.ts#LoroDesktopPersistence

The desktop adapter subscribes to local updates only, so an edit that arrived from
a peer is not echoed back as this window's save. It keeps a pending flag and takes
the snapshot at flush time, after a burst of typing has settled.

### overlay: A synced edit is not a save

The adapter listens for local updates, not every document event. A peer's change
still reaches the board through the projection; what it must not do is make this
window claim the file changed and write it again.

## apps/canvas/desktop/src/main/store.ts#DocumentStore.save

The file authority assembles the envelope, takes the lock and writes atomically.
The renderer never touches the path: it hands over a snapshot, and main decides
where it lands and keeps the previous byte as a backup.

## apps/canvas/packages/graph/src/workspaceFile.test.ts

The reload contract closes the loop: write an envelope, read it into a fresh
document and assert that the board, card and tag survived. The other cases pin the
refusals and the attachment bytes. A save path is only correct while this test
passes.
