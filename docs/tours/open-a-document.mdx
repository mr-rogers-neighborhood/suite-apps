This path follows the desktop open: a path arrives from the command line, a
dialog, a recent or the hub, becomes one open file in main, crosses the preload
bridge as a snapshot, and is projected into the renderer. Each stop is a place
where the path, the bytes or the host answer is settled; the module notes own the
rules. The [Canvas handbook](../../legacy/canvas/handbook/) owns the interface these
files implement; this tour owns the code path.

## legacy/canvas/desktop/src/main/index.ts#attachFile

The pre-ready queue. It accepts only a path whose extension this app opens and
reads nothing, so a cold start can hold the file before `ready` and parse it once
when the window exists. A `suite://` argument does not reach it as a link:
`documentFromArgv` resolves the link against the library first, and a link that
resolves to nothing leaves the launcher. The Desktop / Main note owns the order.

## legacy/canvas/desktop/src/main/index.ts#openDocument

Every open ends here: the command line, a dialog choice, a recent, a link the hub
routed. A new document takes `create` instead. A refusal is a dialog over the
page already showing, so a failed open cannot look like a deleted file; a success
adopts the store and reloads the renderer, which then asks for the identity. The
Desktop / Main note owns the refusal codes and the window.

## legacy/canvas/desktop/src/main/store.ts#DocumentStore.open

Opening is an ordered set of refusals: take the lock, parse the envelope, convert
a legacy file, then try the backups newest first. A damaged file is never
replaced by an empty one; when neither it nor a backup parses, the bytes stay
exactly as they were. The store has two static factories, `open` and `create`,
because a half-open store must not exist to save from. The Desktop / Main note
owns the lock, the write and the mtime guard.

## legacy/canvas/desktop/src/main/index.ts#registerIpc

The page's whole capability set crosses this registration. `loadDocument` hands
over the open snapshot, `saveDocument` creates the file on first save, and
`openDocument` accepts only a path the shell reported earlier. Every handler is
wrapped by `onIpc`, which refuses a sender that is not the page this shell
loaded. The Desktop / Main note owns the seed and the first save.

## legacy/canvas/desktop/src/preload/index.cjs

The allowlist, not a pass-through. `contextBridge` publishes the named methods
and the three host values; with `contextIsolation` on, the page can reach nothing
else. Save takes no path at all, and open takes back only one main reported
earlier and re-checks. A sandboxed preload cannot import the shared channel
constants, so `preload.test.ts` compares the names spelled here. The Canvas
Desktop / Preload note owns the boundary.

## legacy/canvas/src/host/bridge.ts#desktopBridge

The host signal. Its presence means the page is in the shell, not that a build
flag was set; it requires the marker and a version because those are what an
older preload still publishes. The callable half is checked separately, because
a missing method is a version mismatch rather than a reason to write elsewhere.
The Canvas / Host note owns the required list.

## legacy/canvas/src/main.tsx#bootDesktop

The desktop answer is the open file, not the address bar: the shell says which
document is open, and the session is configured from it before `App` and the
store are imported. The store reads the session once at import, so a later answer
would key the document to nothing. `boot` refuses a missing method before this
runs. The Canvas / Host note owns the mismatch, and the Canvas note owns the boot
order.

## legacy/canvas/src/App.tsx#App

With no workspace the shell renders the launcher; with one it renders the canvas.
A successful desktop open owns the window, so the launcher is the state for "no
file", not a page the address bar can return to. The shell opens it first even
when a file was handed over, which is what leaves a place to work when the open
is refused. `App` reads the session and the store; it neither parses the file nor
chooses the adapter. The Canvas note owns the surface.

## legacy/canvas/src/storage/desktopPersistence.ts#LoroDesktopPersistence

The adapter hydrates from the snapshot the boot already took, so a large document
does not cross the boundary twice, and it subscribes to local updates only: an
update that arrived from sync must not be echoed back as a save. Its pending flag
is a "something changed" bit; the snapshot is taken at write time, after the
edits settle. The Canvas / Storage note owns the coalescing and the failure path.

## legacy/canvas/src/store/useCanvasStore.ts#useCanvasStore

The store holds the live document the adapter hydrated. `ready` keeps the canvas
from painting before hydration finishes, and `flush` asks persistence to catch up
before the window leaves the workspace. It holds the document instance, not a
copy of its records, and a refused write never becomes document state. The Canvas
/ Store note owns what may live in the store.

## legacy/canvas/packages/graph/src/workspaceFile.ts#tryParseWorkspaceFile

Parsing answers with a `Result` because the person chose the file and needs a
sentence they can act on. It never merges into an open document; the caller gives
it a new workspace id. A missing image is reported as damaged while the rest of
the document imports. The Graph note owns the envelope and the version refusals.

## legacy/canvas/packages/graph/src/workspaceFile.test.ts

The reload contract is the end of the path: the first case writes an envelope,
reads it into a fresh document and asserts that the board, card and tag survived.
The other cases pin the refusals and the attachment bytes. The Graph note owns
what a weakened case would change.
