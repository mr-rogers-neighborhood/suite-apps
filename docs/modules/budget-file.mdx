The file module owns the two serialized shapes Budget writes: the `.budget`
envelope around a Loro snapshot, and the records envelope a person or another
tool can read. It also validates record references and renders CSV and QIF
exports. It does not choose a path, write bytes, keep backups or open a document;
main owns those, and `decodeBudgetFile` only recognizes bytes it can hand to
`BudgetDocument.fromSnapshot`.

The two shapes have different jobs. A snapshot preserves the CRDT history and
identity, so a `.budget` file is the live format. A records file flattens the
roots into JSON, so it can be inspected, edited or imported by another build
even though concurrent-edit history is lost. Neither decoder validates the
ledger itself; the caller opens the document and validates the records it now
holds.

The failure boundary is explicit. Decoding returns a `Result` with a named code
instead of throwing, and a version refusal is terminal: an older build must not
fall through to a backup or to the records parser and then write its own schema
over a document it does not understand.

## packs/budget/packages/core/src/file/budgetFile.ts#BudgetFileEnvelope

A `.budget` file is JSON, not a zip and not a bare snapshot. The envelope names
the format (`suite.budget`), a file version, the schema version that wrote it,
an export timestamp and a base64 snapshot. Keeping the snapshot opaque lets a
build refuse a file it cannot understand before a CRDT parser touches it, and
the timestamp is evidence for a person rather than a merge input. There is no
path or library id in the envelope; those belong to main.

## packs/budget/packages/core/src/file/budgetFile.ts#encodeBudgetFile

Encoding is pure: it commits the document, exports a snapshot, base64s it and
pretty-prints the JSON with a trailing newline. The schema version comes from
the document's meta, falling back to the current constant, so an older document
is labelled with the schema it actually carries. It does not write; main decides
where and how to replace the file.

## packs/budget/packages/core/src/file/budgetFile.ts#decodeBudgetFile

Decoding is the trust boundary for a file a person chose. It parses JSON, checks
the envelope shape, refuses a newer format version, refuses a newer schema, and
only then decodes the snapshot; every refusal is a `Result` with a code. It
returns raw bytes rather than a document, so version policy and CRDT opening
stay separate. It does not validate the records inside the snapshot; the caller
must open and validate them.

## packs/budget/packages/core/src/file/budgetFile.ts#BudgetFileError

`BudgetFileError` carries a small code beside the message: `not-json`,
`wrong-format`, `unsupported-version`, `unsupported-schema` and `bad-snapshot`.
The codes exist so the library can treat a newer file as terminal and tell the
person which version to use, instead of falling through to a backup or to the
records parser as if the file were damaged. The message is for display; callers
branch on the code.

## packs/budget/packages/core/src/file/recordsFile.ts#recordsEnvelopeSchema

The records envelope is the readable counterpart: one JSON object with every
root array, validated by Zod as a whole. Parsing the whole object is deliberate,
because a default on a later field must be applied in one place and an unknown
record shape should fail before any record reaches a document.
`scheduleBatches` defaults to empty so older exports still load; the other roots
are required.

## packs/budget/packages/core/src/file/recordsFile.ts#decodeRecords

Decoding a records file is a rebuild, not a merge. After JSON and format-version
checks, the whole envelope is schema-parsed, then `validateReferences` runs; the
result is a `BudgetSnapshot` with no CRDT history. A validation failure returns
every problem it found, which is why the error type carries a `problems` list.
The caller turns that snapshot into a new document with
`BudgetDocument.fromRecords`.

## packs/budget/packages/core/src/file/recordsFile.ts#encodeRecords

Encoding flattens a snapshot back into the records envelope: meta, settings,
every root, and the schema version the snapshot names. It is for interchange and
inspection, not for the live file; a records file loses concurrent-edit history
even though it preserves ids. It is also the fallback import shape when a file
is not a `.budget` envelope.

## packs/budget/packages/core/src/file/recordsFile.ts#validateReferences

A CRDT map has no foreign keys, so a records file can parse and still point at a
missing account, category, payee, parent, dashboard or transfer account. This
function checks both directions: ids unique within each id-keyed root it checks,
and every reference resolvable, with Ready to Assign allowed as a category. It returns
messages rather than throwing, so a caller can show all the broken rows at once.

## packs/budget/packages/core/src/file/export.ts#transactionsToCsv

CSV is a flat presentation of transactions, so a split parent is replaced by one
row per child and the parent itself is omitted; the child's category becomes the
category column. Amounts go through the display formatter, which keeps the
integer minor units until the last division, and cells are quoted only when
needed. The function returns text; it never writes a file.

## packs/budget/packages/core/src/file/export.ts#transactionsToQif

QIF carries the same ledger into a format other finance tools read: a transfer
becomes an account link, a categorized row becomes a category link, and a split
parent becomes split lines under one entry. Cleared and reconciled rows get the
QIF markers, and dates are assembled from the date key rather than reparsed.
Like CSV, it is pure text and leaves the write to main.
