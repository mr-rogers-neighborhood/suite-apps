The renderer is the person's side of Planner. It holds a replica of the open
workspace, a Zustand store for what the view is showing, and the React surfaces
that read a derived snapshot. It talks to main only through `PlannerBridge`, and
its bundle has no network client.

It does not own document truth. Every task, project, tag and setting lives in
the replica's `WorkspaceDocument`; the store holds the selected date, the active
view, the selected task, the capture focus signal and a notice. A local edit is
merged into the replica and forwarded as a CRDT delta; an import or a synced
replacement swaps the replica and re-subscribes.

Two rules keep the boundary visible. The single `observe` call site lives in the
snapshot store, so no component subscribes to the document directly. And the
views registry is the one list of surfaces, so the shell and the compact view
menu render the same entries.

## apps/planner/src/renderer/src/store/snapshotStore.ts#DocumentReplica

This class is the renderer's replica and its only `observe` call site. A local
update is forwarded to main, then the cached snapshot is rebuilt and listeners
are notified, which is what makes a component read a value rather than subscribe
to a CRDT. The document is exposed for mutations; the snapshot is what the UI
renders.

`replace` is the boundary for import and sync. It detaches the old subscription
before opening the new document, so an observer of the closed workspace cannot
keep committing edits. `dispose` clears both the subscription and the listeners,
which is the path a closed window takes.

## apps/planner/src/renderer/src/task/TaskNotesEditor.tsx#TaskNotesEditor

The note editor is a Tiptap 3 view over the task's Loro map, not a controlled
input. `LoroNoteSync` returns `LoroSyncPlugin` from `loro-prosemirror`, and each
ProseMirror transaction writes into the replica's document; the replica's one
`observe` subscription forwards that update to main, which is why there is no
save button and no `onChange` value to keep in React.

`StarterKit` is narrowed to the formatting the toolbar offers: paragraphs,
H1–H3, bold, italic, inline code, links, bullet and ordered lists. The toolbar
keeps the selection by cancelling the pointer's default focus move and returns
focus with the command. The editor carries the **Notes** label, a description
that says changes save as you type, and Escape closes the dialog while it has
focus. `plainTextToContent` seeds an old note as hard-broken lines; once the map
exists, the plugin loads it and the seed is ignored.

## apps/planner/src/renderer/src/app/Shell.tsx#Shell

The shell composes the shared menu bar with the active view. It reads the view
id from the UI store, resolves the component from the views registry, and asks
the bridge for the workspace file's name for the bar's context. The rail is the
full navigation; below `md` the same entries move into a drawer.

The shell holds no document state and makes no projection. A new surface is an
entry in the registry and its component, not an edit here. The native menu is
auto-hidden on Linux and Windows, so this in-app bar stays the visible menu
rather than drawing a second copy beside it.
