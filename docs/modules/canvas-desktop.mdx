The desktop package is the Canvas renderer in a shell that owns a file. The two
processes are separate modules: `src/main` owns the window, the IPC and the file,
and `src/preload` publishes the bridge. This module owns the scripts that start
and stage that shell; it does not own the document model or the canvas surface.

The package's seam is a renderer URL. `shell.mjs` starts Electron against a Vite
server when one is running and against the built bundle otherwise, which is the
same choice the shell makes again in `rendererUrl.ts`. A packaged window and a
development window therefore load the same origin by the same rule.

## legacy/canvas/desktop/scripts/shell.mjs

This is a developer entry point, not the app. It refuses to start when neither a
dev-server URL nor a built bundle exists, because a window with no renderer would
fail later with a less useful message. The child's exit code is preserved: a
signal must not look like a clean window close, or the watcher stops instead of
restarting.

## legacy/canvas/desktop/scripts/watch.mjs#restart

A main-process change replaces the process rather than hot-swapping state the
main process owns: the file, the lock, the backup timer and the single-instance
lock. Waiting for the old process to exit is the invariant; starting the
replacement first makes Electron answer its own lock and quit. The generation
counter keeps a replaced process's exit from ending the loop.

## legacy/canvas/desktop/scripts/stage.mjs

The preload is CommonJS and outside `tsc`, so copying it is the only build step
compilation does not perform. A stale copy would leave the renderer with an old
bridge while main moved on; `preload.test.ts` compares the channel names across
that boundary.
