title: Canvas Desktop / Main
summary: "The Electron main process: one window, one document and the file authority behind both."
---

Main is a file authority, not a document authority. The renderer already owns the
schema, the editors and the attachment store; main owns what a sandboxed page
cannot: the single instance, the window, the open dialog, the file lock, the
atomic write, the backups and the mtime guard. A save therefore crosses the
boundary as a whole snapshot rather than as a stream of edits.

`src/shared/ipc.ts` and `src/preload` name the capabilities the page receives.
Every handler checks its sender, and no channel accepts a destination path from
the page: the page says what to save, main decides where. Sync is wired in the
same process, but it is opt-in per workspace and separate from the file path.

## legacy/canvas/desktop/src/main/index.ts#openDocument

Every way to open a file ends here: the command line, the dialog, a recent, a
link the hub routed. A refusal is shown over whatever the window already had, so
losing the open cannot look like the file is gone. A success adopts the store and
reloads the renderer before the new document is announced.

## legacy/canvas/desktop/src/main/index.ts#attachFile

A file handed to a cold start is queued only when its extension is one this app
opens. The gate is cheaper and narrower than the parser, which runs after the app
is ready. A link is resolved against the library by `documentFromArgv` first, so a
`suite://` argument is never treated as a path.

## legacy/canvas/desktop/src/main/index.ts#createWindow

The window policy is part of the file guarantee: sandbox, `contextIsolation`, no
Node in the renderer, and no navigation away from the bundle. The close handler
flushes before destroying the window, so the debounce window is not lost on quit.
Rendering starts hidden so a white frame never covers the document being opened.

## legacy/canvas/desktop/src/main/index.ts#registerIpc

This is the renderer's whole capability set. `loadDocument` hands over the open
snapshot; `saveDocument` creates a file when none exists, so the first save is not
a separate renderer path; `openDocument` accepts only a path this process already
reported. Every handler is wrapped by `onIpc`, which refuses a sender that is not
the page this shell loaded.

## legacy/canvas/desktop/src/main/store.ts#DocumentStore

One open file and one writer. The class holds the lock, the last written size and
mtime, the debounce timer and the pending attachment set together, so those
cannot drift apart between open and save. It is constructed only through `open`
and `create`, both of which refuse rather than return a half-open store.

## legacy/canvas/desktop/src/main/store.ts#DocumentStore.open

The order is the guarantee: take the lock, parse the envelope, convert a legacy
file, then try backups. A damaged file is never replaced by an empty one; when
neither it nor a backup parses, the open fails and the bytes are left exactly as
they were. The tests name the failures: a second open, a converted file, a
damaged file and recovery from a backup.

## legacy/canvas/desktop/src/main/store.ts#DocumentStore.save

A save is queued, not performed. The newest snapshot replaces an earlier pending
one because the snapshot is the whole state, so writing the intermediate ones
would be wasted work. A malformed request stops the store instead of writing a
partial document, and that sticky failure is what the user is shown. The debounce
lives here, so a menu Save and an autosave share one rule.

## legacy/canvas/desktop/src/main/store.ts#DocumentStore.write

The mtime guard runs before the write. If the file changed since this session
last wrote it, saving stops with `changed-on-disk` rather than overwriting an
outside edit from a sync client, an editor or a restore. The envelope is
assembled through the graph's builder and written atomically, so a crash leaves
the previous version instead of a truncated file.

## legacy/canvas/desktop/src/main/lock.ts#acquireLock

Two processes writing one file lose the loser's work with no error anywhere, so
the second is refused rather than warned. A lock from this machine goes stale
when its heartbeat stops; a lock from another machine never does, because a clock
difference or a sleeping laptop would otherwise let two machines write. Release
removes only the lock this instance wrote.
