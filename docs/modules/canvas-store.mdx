This module is the renderer's state boundary. `useCanvasStore` creates the one
`WorkspaceDocument` a tab edits, chooses the persistence adapter for the host and
holds the sync bridge. The rest of the directory is UI state and the projection
that turns document changes into React values.

It owns the live document instance, the `ready` and `synced` gates, selection and
panel state, and the snapshot store that subscribes to Loro. It deliberately does
not own document truth: no card, board or edge is stored in Zustand, React state
or localStorage. A component reads the document through a selector and writes it
through the graph's facade; the stores only remember which document is open and
what the interface is doing.

## legacy/canvas/src/store/useCanvasStore.ts#useCanvasStore

One document per tab, created at module load after the session has settled. The
store holds the `WorkspaceDocument`, the presence stores, the persistence adapter
and the sync client's status, but never a copy of the graph. Its actions call the
adapter or the bridge; they do not parse a card or rebuild a board.

The adapter is chosen from the host signal, not a build flag, so the same bundle
writes to IndexedDB in a browser and to the shell's file on the desktop. A store
that imported `App` or created its document before the session resolved would key
the document to nothing, which is why the entry point settles the session first.

## legacy/canvas/src/store/useCanvasStore.ts#ROOM_ID

The room is the identity a local copy and a sync session are keyed by. It is the
workspace id for the owner and a projection id for a share, so a viewer never
loads the owner's cached workspace just because both links name the same board.
The room comes from the session, not from a URL param read here.

## legacy/canvas/src/store/useCanvasStore.ts#persistence

The local copy is an adapter behind three methods: load, write and flush. The
store does not know whether those bytes go to IndexedDB or to a file owned by the
main process, and that is what keeps a browser build from growing a second save
path. A failed write is reported through the adapter rather than thrown into a
React render.

## legacy/canvas/src/store/workspaceSnapshotStore.ts#WorkspaceSnapshotStore

The projection is derived, not stored. The class subscribes to the document's
observer, applies one change to the previous snapshot and keeps array identity
for sections that did not move. That is what lets a selector re-render only the
card whose record changed instead of the whole canvas.

The class also owns the text subscription because card bodies carry no record
change; one stream serves every text consumer and stops when the last one
unsubscribes. Destroying the store unsubscribes both, so a closed workspace does
not keep the document alive. `refresh` re-reads the whole document when hydration
or the first sync lands between the initial read and the observer registration;
it merges into the existing snapshot so unchanged sections keep their identity.

## legacy/canvas/src/store/workspaceSnapshotStore.ts#workspaceSnapshotStore

One snapshot store per live `WorkspaceDocument`, held in a `WeakMap`. Two
components that call the hook for the same document share one subscription and
one cache; a new document gets a new store without an explicit teardown step.

## legacy/canvas/src/store/workspaceStore.ts#useWorkspaceSnapshot

The whole-workspace binding for consumers that genuinely read several sections.
It refreshes the projection when `ready` or `synced` changes, then reads through
`useSyncExternalStore`, so React sees the document, not a Zustand mirror of it.

## legacy/canvas/src/store/workspaceStore.ts#useCard

The narrow form of the same binding. A card consumer subscribes to one lookup
keyed by id, so moving another card or renaming a board does not re-render it.
The record objects come from the graph and keep identity, which is what makes the
subscription cheap.

## legacy/canvas/src/store/useUiStore.ts#useUiStore

Selection, panels, menus, viewport and the library scope live here because they
are interface state, not document state. A reload may forget them without losing
work. A field that a second device should see belongs in the graph instead; a
field that only this window needs belongs here.

## legacy/canvas/src/store/projectionStore.ts#useProjectionStore

A projection is a persisted view preference: which board is floating, where it
sits and which corner it snaps to. It is deliberately localStorage-backed because
it describes this window's presentation, not the document's content. Losing it
changes the view, never the workspace.
