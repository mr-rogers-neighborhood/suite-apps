# Android

The native side of Suite Go, and the three places it needs care.

## The SDK this project expects

`android/variables.gradle` is generated by `cap add android` and committed. It carries the
versions the build compiles against:

| Setting                                  | Value  | Note                                                                              |
| ---------------------------------------- | ------ | --------------------------------------------------------------------------------- |
| `compileSdkVersion` / `targetSdkVersion` | 36     | The SDK platform must be installed                                                |
| `minSdkVersion`                          | 24     | Android 7.0                                                                       |
| Android Gradle Plugin                    | 8.13.0 | Wants build-tools 35, not whatever happened to be installed                       |
| Gradle                                   | 8.14.3 | Run it on JDK 17 or 21; a newer JDK fails with a message that never names the JDK |

A distribution that installs the SDK through its package manager makes the SDK directory root-owned,
which means Gradle cannot fetch a component AGP asks for. `pnpm run doctor` reports the state, and a
failed build prints the exact `sudo sdkmanager` command for the missing component rather than a stack
trace.

## Installing it without root

Everything can live under `~/Android`, which the user owns, so Gradle can write the components it
fetches and no `sudo` is involved. `scripts/preflight.mjs` already looks in `~/Android/Sdk`, and it
finds a JDK at `~/Android/jdk-21` or `~/Android/jdk-17` without any variable; `SUITE_GO_JAVA_HOME`
names one that lives somewhere else.

```sh
# Command-line tools, unpacked so sdkmanager lands in cmdline-tools/latest.
mkdir -p ~/Android/Sdk/cmdline-tools
curl -LO https://dl.google.com/android/repository/commandlinetools-linux-16111833_latest.zip
unzip -q commandlinetools-linux-16111833_latest.zip -d /tmp/cmdline-tools
mv /tmp/cmdline-tools/cmdline-tools ~/Android/Sdk/cmdline-tools/latest

# JDK 21, user-owned. Gradle 8.14.3 rejects newer, and this distribution ships none.
curl -L 'https://api.adoptium.net/v3/binary/latest/21/ga/linux/x64/jdk/hotspot/normal/eclipse' \
  -o /tmp/jdk21.tar.gz
tar -xzf /tmp/jdk21.tar.gz -C ~/Android
mv ~/Android/jdk-21.* ~/Android/jdk-21
export JAVA_HOME="$HOME/Android/jdk-21"
export SUITE_GO_JAVA_HOME="$JAVA_HOME"

export ANDROID_HOME="$HOME/Android/Sdk"
SDKMANAGER="$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager"
yes | "$SDKMANAGER" --sdk_root="$ANDROID_HOME" --licenses
"$SDKMANAGER" --sdk_root="$ANDROID_HOME" \
  platform-tools emulator platforms/android-36 build-tools/35.0.0 build-tools/36.0.0 \
  system-images/android-36/aosp_atd/x86_64

echo no | "$ANDROID_HOME/cmdline-tools/latest/bin/avdmanager" create avd \
  -n suite-go-atd -k "system-images;android-36;aosp_atd;x86_64" -d pixel_7
```

Command-line tools 23 accepts the licences during install, so `--licenses` is a no-op there; older
releases need it. Both build-tools 35 and 36 are installed because AGP asks for 35 against a platform
36. `pnpm run doctor` reports each piece — `pnpm doctor` is pnpm's own command, not this project's.

Boot the AVD, then run the loop:

```sh
mise exec -- pnpm android:emulator --start suite-go-atd
mise exec -- pnpm android:install
mise exec -- pnpm android:eval "document.title"
```

`android:emulator --start` waits on the serial adb reports, not on `emulator-<name>`: adb names an
emulator by the port it landed on (`emulator-5554`), so the AVD name never matches a serial. It is
safe to run while that AVD is already up — it finds the running emulator and leaves it alone — and it
detaches the emulator, so the terminal comes back for `android:install`.

The ATD image has a stub display: `adb screencap` returns an all-black frame and `screenrecord`
writes zero bytes, with the host GPU and with `-gpu guest` alike. That is measured, not inferred —
the two modes produce the same file down to the checksum. So a screenshot cannot prove anything on
this image, and an empty black home (`com.android.fakesystemapp/.local…EmptyHomeActivity`) is what a
freshly booted emulator shows rather than a hang. Verify through `android:eval` and `android:ax`,
which read the WebView directly, and take a screenshot only from a non-ATD image.

The equivalent by hand, for a window or a different renderer:

```sh
"$ANDROID_HOME/emulator/emulator" -avd suite-go-atd -no-window -no-audio \
  -no-boot-anim -gpu guest -feature -Vulkan -no-snapshot-load
```

`-gpu guest` is the software renderer; `swiftshader_indirect` segfaulted emulator 37.3.10 on this
machine. `mise exec` supplies the Node and pnpm pinned in `package.json`; the pnpm scripts export
`JAVA_HOME` from the JDK they resolve, and a `gradlew` run by hand needs that path exported as
`SUITE_GO_JAVA_HOME`. `android:install` ends with `installed` and starts
`run.suite.go/.MainActivity`; `android:eval` prints the value, here `Suite Go`.

## The share intent

`android/app/src/main/AndroidManifest.xml` holds the only hand-edited part of the generated project:
the `ACTION_SEND` intent filter on `MainActivity`, which is what puts Suite Go in Android's share
sheet.

`cap sync` does not rewrite the manifest, so the edit survives. `cap add android` does not, so it does
not — regenerating the project loses it. If the filter ever disappears, the app simply stops appearing
in the share sheet, which is quiet enough to go unnoticed for a while.

## Why the app is a real APK in the dev loop

`pnpm android:watch` rebuilds and reinstalls an APK on every save, rather than serving a live-reload
WebView. The things being developed here are native-adjacent: an intent filter, a cold start, the
WebView's own WASM implementation. A live-reload session exercises none of them.

## Testing on GrapheneOS

The target device is a de-Googled Android, and that is a better signal than a stock one for this app:

- **Vanadium is the WebView.** Hardened Chromium with hardened_malloc. Loro is WASM, and if it runs
  there it runs anywhere.
- **No Play Services, no Play Integrity, no Firebase.** The no-telemetry promise is enforced by the
  platform rather than by discipline.
- **Per-app network permission** can be revoked entirely. The container must not assume it has a
  network — which it does not, because v0 has no transport.

Memory Tagging Extension on newer Pixels can surface latent native crashes the emulator will not
reproduce. That is a feature of the test, not a bug in the app.
